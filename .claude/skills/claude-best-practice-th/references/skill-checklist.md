# เช็กลิสต์สร้าง/ตรวจสกิล

## โครงสร้าง
```
.claude/skills/<ชื่อสกิล>/
├── SKILL.md          ← จำเป็น (คู่มือหลัก)
├── scripts/          ← สคริปต์ให้ Claude เรียกใช้ แทนการเขียนโค้ดใหม่ทุกครั้ง
├── references/       ← เอกสารยาว ๆ ที่โหลดเฉพาะเมื่อจำเป็น
└── examples/         ← ตัวอย่างผลลัพธ์ที่ดี
```
สกิลคือ "โฟลเดอร์" ไม่ใช่แค่ไฟล์เดียว ให้แยกเนื้อหายาวไปไว้ใน references/ เพื่อให้ SKILL.md สั้น (เรียกว่า progressive disclosure คือเปิดเผยข้อมูลทีละชั้นตามความจำเป็น)

## ส่วนหัว (frontmatter) ที่ใช้บ่อย
```yaml
---
name: ชื่อ-สกิล                # ใช้เป็นคำสั่ง /ชื่อ-สกิล
description: ทำอะไร + ใช้เมื่อไร (ใส่คำที่ผู้ใช้มักพิมพ์)
argument-hint: "[ไฟล์]"        # คำใบ้ตอนพิมพ์คำสั่ง
allowed-tools:                 # เครื่องมือที่ใช้ได้โดยไม่ต้องขออนุญาต (ใส่ให้แคบที่สุด)
  - "Bash(python3 *myscript.py*)"
disable-model-invocation: true # ให้ทำงานเฉพาะเมื่อพิมพ์ /ชื่อ เท่านั้น
context: fork                  # รันในบริบทแยก ส่งกลับแค่ผลลัพธ์
---
```

## เช็กลิสต์คุณภาพ
- [ ] **description เขียนเป็นตัวกระตุ้น ไม่ใช่บทสรุป** ต้องตอบว่า "เมื่อไรควรใช้" และมีคำที่ผู้ใช้พิมพ์จริง
- [ ] **ไม่สอนสิ่งที่ Claude รู้อยู่แล้ว** ให้เน้นสิ่งที่ต่างจากพฤติกรรมปกติของ Claude
- [ ] **ให้เป้าหมายและข้อจำกัด ไม่บังคับทุกขั้นตอน** Claude จะปรับตัวกับสถานการณ์ได้ดีกว่า
- [ ] **มีหัวข้อ Gotchas** (จุดที่มักพลาด) และเพิ่มทุกครั้งที่เจอ Claude ทำผิด เพราะเป็นเนื้อหาที่มีค่าที่สุด
- [ ] **งานซ้ำ ๆ ใส่เป็นสคริปต์** Claude จะได้เรียกใช้ ไม่ต้องเขียนโค้ดใหม่ทุกครั้ง
- [ ] **ระบุวิธีตรวจผลลัพธ์**
- [ ] **ไม่มีรหัสผ่านหรือ API key อยู่ในไฟล์**
- [ ] **allowed-tools แคบที่สุดเท่าที่ทำได้** (ห้ามใช้ `Bash(*)`)
- [ ] **ทดสอบจริง** โดยเปิดเซสชันใหม่ พิมพ์คำที่ผู้ใช้น่าจะพิมพ์ แล้วดูว่าสกิลถูกเรียกใช้หรือไม่
