# เคล็ดลับ Claude Code (แปลและเรียบเรียง)

ที่มา: หมวด "Tips and Tricks" ใน shanraisshan/claude-code-best-practice ซึ่งรวบรวมจากทีมผู้สร้าง Claude Code (Boris Cherny, Thariq) และชุมชน

## การสั่งงาน (Prompting)
- **ท้าทาย Claude**: เช่น "ถามฉันเกี่ยวกับการแก้ไขนี้ จนกว่าฉันจะตอบผ่าน" หรือ "พิสูจน์ให้ดูว่าใช้ได้จริง"
- **ถ้าแก้มาแล้วได้ผลแค่พอใช้**: สั่งว่า "จากที่รู้ทั้งหมดตอนนี้ ทิ้งของเดิม แล้วทำใหม่แบบที่ดีที่สุด"
- **เจอบั๊ก**: แปะข้อความ error แล้วสั่ง "แก้" ได้เลย ไม่ต้องบอกวิธีแก้ทีละขั้น

## การวางแผน
- **เริ่มงานใหญ่ด้วย Plan mode เสมอ**
- **ให้ Claude สัมภาษณ์คุณ**: เขียนโจทย์สั้น ๆ แล้วให้ Claude ถามคำถามจนชัดเจน จากนั้นเปิดเซสชันใหม่เพื่อลงมือทำ
- **แบ่งแผนเป็นช่วง**: แต่ละช่วงต้องมีการทดสอบก่อนไปช่วงถัดไป
- **แบ่งงานเป็นชิ้นที่ใช้งานได้ครบตั้งแต่ต้นจนจบ**: เช่น ทำฟีเจอร์เล็ก ๆ ให้ครบทั้งฐานข้อมูล ระบบหลังบ้าน และหน้าจอ แทนการทำฐานข้อมูลให้เสร็จทั้งหมดก่อน
- **ให้ Claude อีกตัวช่วยรีวิวแผน**: ให้รีวิวในบทบาทวิศวกรอาวุโส
- **ทำต้นแบบหลายแบบดีกว่าเขียนสเปกยาว**: เพราะการลองทำมีต้นทุนต่ำ

## บริบท (Context)
- **คุณภาพเริ่มตกเมื่อใช้บริบทราว 40%**: มือใหม่ควรใช้ไม่เกิน 40% ถ้าถึง 60% ให้เริ่มเก็บงาน
- **ถอยดีกว่าแก้ทับ**: กด Esc สองครั้ง หรือพิมพ์ `/rewind` เพื่อย้อนกลับไปก่อนจุดที่พลาด แล้วสั่งใหม่โดยใส่สิ่งที่ได้เรียนรู้ ดีกว่าแก้ทับไปเรื่อย ๆ จนบริบทรก
- **`/compact` พร้อมคำใบ้**: เช่น `/compact เน้นเรื่องระบบล็อกอิน ตัดส่วนดีบักทิ้ง` ได้ผลดีกว่าปล่อยให้ระบบย่อบริบทเอง
- **ใช้ subagent กับงานค้นหา**: ถามตัวเองว่า "ต้องใช้ผลลัพธ์ระหว่างทางอีกไหม หรือต้องการแค่ข้อสรุป" ถ้าต้องการแค่ข้อสรุป ให้ส่งงานให้ subagent

## การจัดการเซสชัน
- **งานใหม่ = เซสชันใหม่**: งานที่เกี่ยวเนื่องกันใช้เซสชันเดิมได้
- **ก่อนย้อนกลับ**: สั่ง "สรุปจากตรงนี้" เพื่อเก็บโน้ตส่งต่อไว้ก่อน
- **`/compact` กับ `/clear` ต่างกันอย่างไร**:
  - `/compact`: ย่อบริบทให้ทำงานต่อได้ลื่น แต่รายละเอียดบางส่วนหายไป
  - `/clear` + สรุปเอง: ล้างทั้งหมด แต่คุณควบคุมได้เองว่าจะส่งอะไรต่อ เหมาะกับงานสำคัญ
- **เซสชันสำคัญ**: ตั้งชื่อด้วย `/rename` แล้วกลับมาทำต่อด้วย `/resume`

## CLAUDE.md และ Rules
- **CLAUDE.md ไม่ควรเกิน 200 บรรทัด**: ยิ่งสั้นยิ่งดี บางทีมใช้แค่ราว 60 บรรทัด
- **ทดสอบ CLAUDE.md**: ทุกคนในทีมต้องเปิด Claude แล้วพิมพ์ "รันเทส" ได้ผลตั้งแต่ครั้งแรก ถ้าไม่ได้ แปลว่า CLAUDE.md ขาดคำสั่งสำคัญ
- **`.claude/rules/*.md` ใช้แยกกติกาเป็นหัวข้อ**: ใส่ `paths:` เพื่อให้โหลดเฉพาะตอนที่แตะไฟล์ที่เกี่ยวข้อง
- **ทำโค้ดให้สะอาดและย้ายระบบให้เสร็จ**: โค้ดที่ย้ายระบบไปครึ่งทางทำให้ Claude สับสนว่าควรใช้แบบไหน
- **พฤติกรรมที่ต้องแน่นอน**: ใส่ใน `settings.json` อย่าเขียนขอร้องไว้ใน CLAUDE.md

## Agent / Subagent
- **ทำ subagent เฉพาะฟีเจอร์ คู่กับสกิล**: ดีกว่า agent กว้าง ๆ อย่าง "QA" หรือ "backend"
- **สั่ง "ใช้ subagents"**: เพื่อกระจายงานหนัก และให้บริบทหลักสะอาด
- **ให้ agent หนึ่งเขียน และอีกตัวรีวิว**: บริบทแยกกันช่วยให้จับบั๊กได้ดีขึ้น แม้จะเป็นโมเดลเดียวกัน

## สกิลและคำสั่ง
- **อะไรที่ทำเกินวันละครั้ง ให้ทำเป็นสกิลหรือคำสั่ง**
- **`context: fork`**: ทำให้สกิลรันในบริบทแยก บริบทหลักจะเห็นแค่ผลลัพธ์
- **สกิลคือโฟลเดอร์**: ใช้ references/, scripts/ และ examples/
- **ทุกสกิลควรมีหัวข้อ Gotchas**: แล้วเพิ่มจุดที่ Claude พลาดไปเรื่อย ๆ
- **description คือตัวกระตุ้น**: เขียนให้โมเดลรู้ว่า "ควรใช้เมื่อไร"
- **ไม่ต้องเขียนสิ่งที่ Claude รู้อยู่แล้ว**: และอย่าบังคับทุกขั้นตอน ให้เป้าหมายและข้อจำกัดแทน
- **ใส่สคริปต์ไว้ในสกิล**: Claude จะได้เรียกใช้ ไม่ต้องเขียนใหม่
- **`` !`คำสั่ง` `` ใน SKILL.md**: ใส่ผลลัพธ์จากคำสั่ง shell เข้าไปในพรอมต์ตอนเรียกใช้สกิล

## Hook
- **PostToolUse hook**: จัดรูปแบบโค้ดอัตโนมัติหลังแก้ไฟล์
- **Stop hook**: เตือนให้ Claude ตรวจงานก่อนจบรอบ
- **Hook เฉพาะสกิล**: เช่น `/careful` ที่บล็อกคำสั่งอันตรายระหว่างใช้สกิล

## การทำงานขั้นสูง
- **`/loop`**: ใช้กับงานซ้ำบนเครื่องตัวเอง
- **`/schedule`**: ใช้กับงานตั้งเวลาบนคลาวด์ ที่ทำงานต่อได้แม้ปิดเครื่อง
- **ตั้งสิทธิ์แบบเจาะจง**: เช่น `Bash(npm run *)` หรือใช้ auto mode แทนการปิดการถามสิทธิ์ทั้งหมด
- **`/sandbox`**: ลดการถามสิทธิ์ได้ เพราะแยกไฟล์และเครือข่ายออกจากเครื่องจริง
- **ลงทุนทำสกิลตรวจผลงาน**: เช่น สกิลทดสอบขั้นตอนสมัครสมาชิก
- **ใช้ diagram ตัวอักษร (ASCII)**: ช่วยให้เข้าใจโครงสร้างระบบ

## Git / PR
- **PR เล็กและโฟกัส**: 1 ฟีเจอร์ต่อ 1 PR
- **รวม commit ตอน merge (squash merge)**: ประวัติจะสะอาด และย้อนกลับง่าย
- **commit บ่อย ๆ**: งานเสร็จเมื่อไรก็ commit
- **ใช้ `/code-review`**: ให้หลาย agent ช่วยหาบั๊กก่อน merge

## ดีบัก
- **ส่งภาพหน้าจอให้ Claude ดู**: ทุกครั้งที่ติดปัญหา
- **ให้ Claude เห็นหน้าเว็บจริง**: ใช้ MCP เบราว์เซอร์ เช่น Playwright หรือ Chrome DevTools
- **อยากดู log**: ให้ Claude รันโปรแกรมนั้นเป็นงานเบื้องหลัง
- **`/doctor`**: ใช้ตรวจปัญหาการติดตั้งหรือการตั้งค่า

## ประจำวัน
- **อัปเดต Claude Code บ่อย ๆ และอ่าน changelog**: เพื่อรู้ฟีเจอร์ใหม่
