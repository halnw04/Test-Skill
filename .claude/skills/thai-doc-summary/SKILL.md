# สรุปเอกสารเป็นภาษาไทย

เป้าหมาย: ผู้อ่านที่ไม่มีเวลา อ่านแค่ 30 วินาทีก็รู้ว่าเอกสารพูดเรื่องอะไร สำคัญอะไร และต้องทำอะไรต่อ

## ระดับความยาว
ผู้ใช้อาจระบุมาในคำสั่ง ถ้าไม่ระบุให้ใช้ "ปกติ"
- **สั้น**: ใจความหลัก 1 ประโยค และประเด็นสำคัญไม่เกิน 3 ข้อ
- **ปกติ**: ใช้ครบทุกหัวข้อในแม่แบบด้านล่าง ประเด็นสำคัญ 3 ถึง 7 ข้อ
- **ละเอียด**: แม่แบบเต็ม และเพิ่มสรุปรายบท/รายส่วนตามโครงสร้างของเอกสารต้นฉบับ

## แม่แบบผลลัพธ์

```
## 📄 สรุป: <ชื่อเอกสาร หรือหัวข้อ>

**ใจความหลัก:** <1-2 ประโยค ตอบว่าเอกสารนี้ต้องการบอกอะไร>

### ประเด็นสำคัญ
- <ประเด็น 1 ขึ้นต้นด้วยข้อเท็จจริง ไม่ใช่คำเกริ่น>
- ...

### ตัวเลข / วันที่ / ชื่อที่ต้องจำ
| รายการ | ค่า | หมายเหตุ |
|---|---|---|

### สิ่งที่ต้องทำต่อ (ถ้ามี)
- [ ] <ใคร> ทำ <อะไร> ภายใน <เมื่อไร>

### ข้อสังเกต
- <จุดที่ไม่ชัดเจน ขัดแย้ง หรือข้อมูลที่ขาดหาย>
```

ตัดหัวข้อที่ไม่มีเนื้อหาออกเลย เช่น เอกสารไม่มีงานที่ต้องทำต่อ ก็ไม่ต้องใส่หัวข้อนั้น

## กติกาสำคัญ (Gotchas)
- **ห้ามแต่งข้อมูล**: ตัวเลข วันที่ ชื่อคน และชื่อบริษัท ต้องตรงกับต้นฉบับทุกตัว ถ้าไม่แน่ใจให้เขียนว่า "(ไม่ระบุในเอกสาร)"
- **คงศัพท์เฉพาะไว้**: ชื่อผลิตภัณฑ์ ชื่อเทคโนโลยี และตัวย่อ ให้คงภาษาอังกฤษไว้ ครั้งแรกที่ใช้ให้วงเล็บคำอธิบายภาษาไทยสั้น ๆ เช่น "API (ช่องทางให้โปรแกรมคุยกัน)"
- **แยกความเห็นออกจากข้อเท็จจริง**: ถ้าผู้เขียนแสดงความเห็น ให้เขียนว่า "ผู้เขียนเห็นว่า..."
- **เอกสารภาษาอังกฤษ**: สรุปเป็นภาษาไทยได้เลย ไม่ต้องแปลทั้งฉบับ
- **เอกสารยาวมาก (เกินประมาณ 30 หน้า)**: สรุปทีละส่วนก่อน แล้วค่อยรวมเป็นสรุปใหญ่ บอกผู้ใช้ด้วยว่าทำแบบนี้
- **ตัวเลขเงิน**: ใช้รูปแบบ 1,234,567 บาท และระบุสกุลเงินตามต้นฉบับ
- **วันที่**: ถ้าต้นฉบับเป็น ค.ศ. ให้คงไว้ ไม่ต้องแปลงเป็น พ.ศ. เว้นแต่ผู้ใช้ขอ
- **อ่านไฟล์ไม่ได้**: เช่น PDF ที่เป็นรูปสแกน ให้บอกผู้ใช้ตรง ๆ อย่าเดาเนื้อหา

## ตรวจก่อนส่ง
1. ตัวเลขและชื่อทุกตัวในสรุป หาเจอในต้นฉบับ
2. ใจความหลักตอบได้ว่า "เอกสารนี้ต้องการบอกอะไร"
3. ไม่มีคำฟุ่มเฟือย เช่น "เอกสารฉบับนี้ได้กล่าวถึง..."
